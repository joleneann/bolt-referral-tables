# The tables, as specified

Transcribed from `Bolt Tables v2.xlsx`, Sheet1, cell notes included. That sheet is the
specification; `supabase/migrations/` implements it. Six tables: the five drawn on the sheet plus
`verification_matrix`, which is the sheet's own matrix stored as data.

## patients

The account list. Source: customer records. A patient may only have one referrer_id.

| column | note |
|---|---|
| patient_id | generated uuid, never reused |
| referrer_id | who referred this person. At most one, set at conversion, never changes |
| successful_referrals | not a column: counted live from released claims by a function the API exposes like a column, so it can never drift. Shows on the patient's referral list |
| first_name, last_name | as registered |
| email, phone | unique. What a claim resolves against |
| address_line, postcode | recorded, shown, never decide anything alone |
| payment_fingerprint | recorded only; not part of the matrix |
| customer_since | set once. Separates a new customer from an existing one arriving on a link |

## claims

One row per discount link click. Source: events. Folks who've clicked a discount link but not
onboarded. One referrer_id may have multiple claim_ids. At least one of friend_email and
friend_phone must be filled. A friend may be claimed by many but released once: the successful
claim keeps it.

| column | note |
|---|---|
| claim_id | generated uuid |
| referrer_id | whose link it was. Fixed at arrival |
| claim_channel | which surface: whatsapp_link, qr_code, sms_link, email_link |
| friend_email, friend_phone | what the friend typed at the claim step. Either one finds them later |
| creation_date | when they arrived |
| expiry_date | creation plus 6 months |
| claim_status | discount_code_clicked (default), account_created (if on friends table), transaction_paid, transaction_delivered, transaction_success |
| friend_patient_id | after an order is complete, friend becomes a patient |

## friends

Onboarded friends. Source: verification records. What each friend typed at registration, and
what the four comparisons run against.

| column | note |
|---|---|
| claim_id | which claim brought them |
| first_name, last_name, email, phone, address_line, postcode | as typed |

## verification_matrix

The rule as sixteen readable rows. Y means that field matches an existing patient, contacts
distinct. Stored as a table so the rule is readable by link: manual when both names match,
else yes.

| first_name | last_name | address | postcode | approved | note |
|---|---|---|---|---|---|
| Y | Y | Y | Y | manual | could be father and son, same name, same address |
| Y | Y | Y | N | manual | could be the same person, sending to a different postcode with coincidence same address |
| Y | Y | N | Y | manual | neighbours with same names |
| Y | Y | N | N | manual | could be the same person sending to a different address |
| Y | N | Y | Y | yes | |
| Y | N | Y | N | yes | |
| Y | N | N | Y | yes | neighbours with the same first name |
| Y | N | N | N | yes | |
| N | Y | Y | Y | yes | family members |
| N | Y | Y | N | yes | |
| N | Y | N | Y | yes | |
| N | Y | N | N | yes | |
| N | N | Y | Y | yes | unrelated housemates |
| N | N | Y | N | yes | |
| N | N | N | Y | yes | |
| N | N | N | N | yes | |

## grant_friend_discount

Job: check the claimant is not an existing patient, then grant their discount. UK photo IDs
do not necessarily have id numbers to dedupe with, so a name conflict needs a manual photo ID
check. friend_patient_id is copied from the claim so the database can refuse a second release
per friend.

| column | note |
|---|---|
| claim_id | one row per claim |
| first_name_match, last_name_match, address_match, postcode_match | yes or no, against an existing patient, contacts distinct |
| manual_verification_needed | generated by the database: yes when both name columns are yes |
| manual_approved | NA, yes or no. The human photo ID verdict |
| approved | NA, yes or no |
| verdict_note | copied from verification_matrix at decision time, so the record keeps what was actually shown |
| within_window | yes or no, check expiry date |
| release_friend_discount | approved and within_window both yes, and no earlier release for this friend: the database refuses a second release per friend |
| transaction_status | paid, delivered, success |
| friend_patient_id | carries the one-release-per-friend index |

## grant_patient_discount

Job: check if the referrer can get their bonus. Source: order records. referrer_id is copied
from the claim so the database can refuse a second 80 for the same referrer.

| column | note |
|---|---|
| claim_id | one row per claim |
| referrer_id | carries the one-80-per-referrer index |
| transaction_status | paid, delivered, success. This will show on the patient's referral list |
| transaction_success | yes or no |
| first_claim | yes if the referrer's successful_referrals is 0, no if 1 or more. Counted live, so this can never pay 80 twice |
| referral_amount | 80 if first_claim is yes and 40 if first_claim is no |
| release_patient_discount | transaction_success has to be yes, referral_amount must hold 80 or 40, and the same claim's friend discount must have released, else no |

## The nineteen cases

| # | case | expected |
|---|---|---|
| 1 | Same full name, same address, same postcode | manual photo ID check (could be father and son) |
| 2 | Same full name, same address, different postcode | manual photo ID check (could be the same person) |
| 3 | Same full name, same postcode, different address | manual photo ID check (neighbours with same names) |
| 4 | Same full name, nothing else matches | manual photo ID check (could be the same person) |
| 5 | Same surname, address, postcode and bank card | approved (family members; the card is recorded and decides nothing) |
| 6 | Same address and postcode only | approved (unrelated housemates) |
| 7 | Same first name, same postcode | approved (neighbours with the same first name) |
| 8 | Nothing matches | approved |
| 9 | Friend's email already belongs to a patient | already a customer, no discount, no reward |
| 10 | Existing patient claims under a new email, same name | manual photo ID check catches it |
| 11 | Two customers claim the same friend | successful claim releases, the other never does |
| 12 | Referrer's first successful claim | 80 |
| 13 | Same referrer's second successful claim | 40 |
| 14 | A second 80 attempted for the same referrer | the database refuses it |
| 15 | Window closes with no delivery | lapsed, nothing released |
| 16 | Clicked the link, never registered | stays discount_code_clicked until expiry |
| 17 | Registered, never ordered | discount approved, bonus waits for the order |
| 18 | Manual check still pending | manual_approved NA, nothing released yet |
| 19 | Claimed by phone, registered with an email | still found, approved |
